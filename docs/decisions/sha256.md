# Compute SHA-256 with the sha2 crate through the bridge
@decision sha256 v3
@cites rust-bridge
@cites toml-reader
@cites current-dependencies
Sinter computes SHA-256 with the Rust crate `sha2` 0.11.1, through one function of the parser bridge, behind a SHA-256 interface of Sinter's own in `lib/`.

## Context

Sinter needs SHA-256 for the extent hash, for the block hash that an
`@ack` pins, for the id of a ledger entry, and to check a fetched pack.
The OCaml standard library has no SHA-256: its `Digest` module offers
MD5 and BLAKE2 only. Wasmtime's cache links `sha2` 0.10. In October
2026 Sinter moved to `sha2` 0.11.1 under the record
`current-dependencies`, so the binary holds both versions while
wasmtime needs 0.10.

## Decision

- The bridge exports one function that hashes a string with `sha2`.
  The crate is pinned to an exact version, `=0.11.1`.
- `lib/` holds a SHA-256 interface of Sinter's own. No other module
  sees the crate or the bridge function.
- Tests check the function against the published NIST test values.

## Alternatives considered

- **Stay on `sha2` 0.10.9 while wasmtime links 0.10.** Not chosen: one
  copy of the code in the binary did not outweigh the rule of the
  record `current-dependencies`, with no exception to state.

- **The opam library `digestif` 1.3.1** (MIT). Not chosen: a new
  dependency in the lock file that ships code the binary does not hold
  today.
- **A SHA-256 module of Sinter's own, in OCaml.** Not chosen: hashing
  code to maintain, slower than the crate, and a lot of bit arithmetic
  for the mutation tests to cover.

## Consequences

SHA-256 keeps all outside code behind the bridge, as the record
`toml-reader` does for TOML. The core library's hashing depends on the
bridge. The binary holds two versions of `sha2` while wasmtime links
0.10.
